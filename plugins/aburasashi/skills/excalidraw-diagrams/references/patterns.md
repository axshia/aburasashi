# 図の型

4 つの型の、配置と部品の目安です。
座標は px で、`Scene` のメソッド名を添えています。
すべて架空の例です。

## 1. 現状のシナリオ

誰が、どの画面で、何をすると、どうなるかを、1 行に 1 つの操作で並べます。

- 1 行目に、グレーの列見出し（`text(..., color=COLORS["note"][0])`）を置く: 「誰が」「どの画面で」「何をすると」「どうなるか」。
- 各行の高さは 170〜180px。行の左端に番号、行の間に薄い区切り線（`separator`）を置く。
- 列の目安:
  - 誰が（x≈60）: `person`。人ごとに role を変える（利用者は `actor`、運営は `operator`）。
  - どの画面で（x≈170）: `screen`。押すボタンがあれば `button` に表示中の文言を入れ、画面名を下に書く。
  - 何をすると（x≈400）: 操作の文。画面の文言は「」で引用する。
  - どうなるか（x≈860）: `box`。保存や参照が起きる行だけ、右に `cylinder` と矢印（「保存する」「参照して表示」）を置く。起きない行は、右にグレーで「ストレージには送らない」のように書く。
- 現在の作りに仮の実装があるときは、結果の箱に「（現在は、〜）」と添える。

## 2. 問題

問題が起きない場面と、起きる場面を上下に並べます。
例: `assets/example/problem.py`

- 各場面の左上に「① 〜したとき」「② 〜したとき」の見出しを置く。
- 2 つの場面は同じ配置にし、違う箇所を 1 つだけにする（例: ② にだけ、残った古いファイルを `problem` の色で描く）。
- 場面の間に、何が起きて次の場面になるかを、短い縦の矢印とラベルで書く（「あとで画像を差し替える」）。
- 右端に結果の箱を置く: 起きない場面は `store`（「問題なし」）、起きる場面は `problem`（何が困るか）。

## 3. 時系列の処理

出来事を左から右へ並べ、時間がたってから起きる処理を下に置きます。

- 出来事の箱は横一列（幅 160〜200px、間隔 40〜60px）。人の操作は `actor`、担当者の操作は `operator`。
- 出来事で作られるもの（保存したファイルなど）は、箱の下に `file_chip` で置く。
- 時間の経過は、出来事の箱にしない。最後の箱から下へ `elapsed`（縦の破線の矢印と「一定期間が過ぎる」）を引く。
- その先に処理の箱（`problem` の色と `trash` など）を置き、処理の対象を矢印で直接指す。

## 4. 仕組み

通常の流れと、失敗したときの流れを、レーンに分けます。
例: `assets/example/mechanism.py`

- 各レーンの左上に `lane_title`（「通常のフロー」「リトライしても残った分の再送」）を置き、レーンの間を `separator` で区切る。
- 通常のフローは、起点の出来事 → キューイング → キュー → ワーカー → 行き先の順に `box` と `arrow_between` で並べる。起点は、読み手が知っている操作の名前にする。
- リトライは、ワーカーの下から出てキューへ戻る、`problem` の色の破線の矢印で描き、条件を短く書く（「送信に失敗したらリトライ」）。
- 失敗した分を拾うレーンは、スケジューラ（`schedule`）→ バッチ → 同じ行き先の順に並べる。スケジューラには頻度を括弧で添える。
- 行き先（`cylinder` など）は 2 つのレーンで 1 つだけ描き、両方の矢印をそこへ向ける。
