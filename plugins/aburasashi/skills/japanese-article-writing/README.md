# Japanese Article Writing

[Skill catalog](../README.md)

社外の読者に公開する日本語記事（技術ブログ、ノウハウ・解説記事、比較記事、お知らせ）を、冒頭で読者が自分に関係する記事だと分かり、最初の見出しまでに要点がつかめ、自社や筆者にしか書けない情報で成り立つ文章にするスキルです。
倉島保美『改訂新版 書く技術・伝える技術』の 7 法則（冒頭に総論、パラグラフ、要約文、既知から未知、並列、1 文 1 ポイント、簡潔）を、記事の手順と確認に移しています。
導入の入り方は記事の型で選び、ノウハウや比較の記事では、題材に即した短い場面から入れます。技術ブログと重要なお知らせは、結論から入ります。
比較表は、比較の条件を先に書き、セルを対応、非対応、条件付き、記載なし、要確認の 5 つの表記でそろえます。
材料に一次情報（自社の数字、事例、判断の理由、失敗、意見）がなければ、一般論で埋めずに質問するか、追記箇所を示した草稿を返します。

## 使い方

```text
$japanese-article-writing で、次の社内メモから技術ブログの記事を書いてください。
読者は、同じ規模の Web サービスで同じ問題に困っているエンジニアです。

ここにメモを貼り付けます。
```

```text
$japanese-article-writing で、この下書きを公開できる品質に直してください。
AI が書いたような定型表現と、同じ説明の繰り返しを減らしてください。
```

Claude Code では、プラグイン名を含むスラッシュコマンドでも呼び出せます。

```text
/aburasashi:japanese-article-writing 新機能のお知らせ記事を、次の材料から書いてください。
```

## 書き換えの例

変更前：

> 「会議の録画が見つからない」「社外の人を招待するたびに手間がかかる」。そんな悩みを抱える方も多いのではないでしょうか。この記事では、Web 会議ツールの選び方を解説します。

変更後：

> 取引先との定例会議を Web 会議に移すと決まったら、次はツール選びです。候補の料金表を見比べる前に、決め手にする項目を 1 つ決めておくと、あとで乗り換えずに済みます。
>
> その項目は、録画をどこに何日間保存できるかです。当社のサポートに届く乗り換え相談の半数は、前のツールで録画の保存期間が足りなかったことが理由です。

どの記事にも貼れる悩みの列挙と予告だけの文を、題材に即した場面、結論、一次情報に置き換えています（例の数字は架空です）。
お知らせの記事なら、場面を置かずに結論から入ります。
一次情報が材料になければ、作らずに質問するか、追記する位置を `【要追記】` で示した草稿を返します。

## 適用範囲

- 対象：社外に公開する日本語記事の執筆、書き直し、レビュー。技術ブログ、ノウハウ・解説記事（「〜とは」、提案、比較、手順）、お知らせ・リリース記事。比較記事の表も含みます。
- 対象外：PR 文面（`japanese-pr-writing`）、ユーザーへの返答と社内文書（`japanese-native-writing`）、SEO のキーワード設計とメタディスクリプション、入稿作業、日本語以外の記事。
- 優先するもの：媒体のスタイルガイドと表記規約。
- 通常の入力：記事の材料（社内メモ、事実の一覧、下書き）と想定読者。ネットワークアクセスは不要です。
- 補わない情報：情報源にない数字、事例、体験談、お客様の声、引用、効果、傾向。
