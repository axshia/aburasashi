## 1. 書籍の基本的な考え方

書籍は、仕事の文章の読み手は必要な部分だけを読み、全文は読まないという前提に立ちます。
そのうえで、読み手の負担を減らす条件を 3 つ挙げます。
読む量を減らしても必要な情報が伝わること、一度読めば理解できること、重要な情報が記憶に残ることです。
理解の速さは、読み手が先の展開を予測でき、その予測が当たるかどうかで決まると説明しています（認知心理学のメンタルモデル）。
書き手は内容を知っているので、自分の文章を分かりやすいと感じやすく、その感覚は当てにならない、とも述べています。

検索から来る記事の読者も、必要な情報だけを拾い、途中で読むのをやめます。
このスキルは、書籍の前提を記事にもそのまま当てはめます。
書籍は文章とスピーチを比べ、文章は読み手が読む箇所を選べるので、重要な情報を最初に置くべきだとしています。
記事の結論をまとめで明かす構成は、この考え方に反します。
このスキルは、総論を最初の見出しより前に置く形で、この考え方を当てはめます。記事の最初の一文を総論にすることまでは求めません（8 節）。

## 2. 7 法則と、このスキルでの適用

| 法則 | 書籍の要点 | このスキルでの適用 |
| --- | --- | --- |
| 1. 冒頭に総論 | 冒頭に結論と重要な情報の要約を置き、各論は総論と同じ順に書く。章や節にも総論を置く。総論は具体的に書き、長い文書で 7 文前後、章や節で 1〜4 文。結論は総論と一致させ、新情報を書かない | 導入を総論にする。総論は最初の見出しより前に置き、題材に即した場面から入る導入も認める。見出しの直下に節の総論を置く。まとめの扱い |
| 2. パラグラフ | 1 トピック 1 パラグラフ。パラグラフ同士は縦（論理の接続）か横（並列）でつなぐ。補足は「どういう意味か」「本当か」に答える。文だけなら 4〜8 文が目安 | 構成の手順 2。段落の長さはトピックで決める |
| 3. 要約文 | 各論のパラグラフは冒頭に要約文を置く。1 トピックを 1 文で、具体的に書く。予告だけの文は要約文にならない。要約文だけを読んで論理が通るようにする | 構成の手順 7。送る前の確認 |
| 4. 既知から未知 | 文頭に既出の情報、文末に新しい情報を置く。統一型、引継型、展開型の 3 つの流れ方がある。くどくなってもよい。能動態か受動態かは流れで決まる | 推敲の 1 回目 |
| 5. 並列 | 並列する情報は同じ構成、同じ表現で書く。意味のある順に並べ、抽象度をそろえる。重要度に大差があればそろえない | 構成の手順 6。推敲の 2 回目 |
| 6. 1 文 1 ポイント | 「て、」「り、」「し、」「が、」で別々のポイントを並べない。関係が弱ければ切り、強ければ関係を示してつなぐか、切って接続語を足す。「が、」は避ける。羅列は例外。字数の上限より効果がある | 推敲の 3 回目 |
| 7. 簡潔 | 読み手のニーズと前提知識に合わない情報、類語の重複、冗長な文末、二重否定を直す | 推敲の 4 回目 |

## 3. 文書の型と作成手順

書籍の実践編は、文書を総論、各論、結論の 3 部で組みます。
総論は、目的のパラグラフ（背景、問題点または必要性、目的）と、要約のパラグラフ（まとめの文と、重要な情報 3 つ）からなります。
短い文書では、総論を 2〜3 文にまとめます。
このスキルでは、記事の導入（リード）を要約のパラグラフに当てます。
当初は背景を 1 文までにしていましたが、所有者のレビュー（8 節）を受けて、題材に即した場面を 2〜3 文まで置けるようにしました。
ベースラインで AI 定型として現れたのは、どの記事にも当てはまる悩みの列挙と長い背景で、題材に即した短い場面ではありません。

書籍は作成手順を 11 段階で示します。
仮の総論、パラグラフ構成、並列の当たり付け、要約文、展開、総論の見直し、4 種の確認（既知から未知、並列、1 文 1 ポイント、簡潔さ）、時間をあけた見直し、の順です。
このスキルの手順は、この順をそのまま使います。
最後の段階（3 日ほどあけて見直す）はエージェントにはできないので、要約文だけを抜き出して読む確認に置き換えました。
記事の種類ごとの型は、実践編の 5 つの演習（提案書、調査報告書、技術報告書、回答書、作業指示書）と短い文書の型から作りました。

## 4. 一次情報と読者の目的

Google のガイドは、独自の情報、調査、分析があるか、他の情報源の言い換えを超える価値があるか、実体験や深い知識が示されているかを、自己評価の質問に挙げています。
読者が読み終えたときに目的を果たせるかも問います。
検索エンジンを優先したコンテンツの兆候として、他者の意見の要約にとどまること、決まった文字数を目指すことを挙げ、Google が優先する文字数はないと明記しています。

ベースラインのノウハウ記事は、一次情報のない依頼に、3,000 字の一般論で応えました。
このスキルでは、書く前に一次情報を棚卸しし、なければ質問するか、追記箇所を示した草稿を返す形にしました。
字数の指定があっても一般論で埋めないのは、この観察と Google のガイドに基づく判断です。

## 5. AI 定型

Wikipedia の “Signs of AI writing” は、AI が書いた文章に多い特徴を分類しています。
重要性の誇張、宣伝調、根拠を示さない「専門家は〜」のような帰属、誰も言っていない誤解を否定する対比、3 つ組の列挙、型どおりの結びの節、太字や箇条書きや見出しの多用などです。
同時に、これらは AI が書いた証拠ではなく、人の文章にも現れること、表面の特徴を消すことが目的ではないことを注意しています。

日本語の記事でどう現れるかは、ベースラインで確かめました。
悩みを括弧で並べる導入、「〜ではないでしょうか」、「この記事では〜を解説します」、「〜しましょう」の連続、根拠のない「〜が増えています」、まとめでの再列挙と「ぜひ参考にしてください」、「〜なのです」「〜わけです」、締めの 3 点リストが出ました。
置き換え表は、禁止の一覧ではなく「見つけたら、こう書き換える」の形にしました。
出力の形の問題には、禁止より書き換え先を示すほうが効くためです。
悩みを括弧で並べる導入の行は、当初「結論と一次情報で始める」に書き換えるとしていました。
この行は、題材に即した場面から入る導入まで消すと読めたため、どの記事にも貼れる煽りだけを対象にすると明記しました（8 節）。

## 6. 書籍の規則と一般的な助言がぶつかる点

| 論点 | 一般的な助言 | 書籍の立場 | 採用 |
| --- | --- | --- | --- |
| 受動態 | 能動態にする | 既出の情報を文頭に置けるほうを選ぶ | 書籍 |
| 1 文の長さ | 40 字以内など字数で決める | 1 文 1 ポイントで決める | 書籍 |
| 導入 | オウンドメディアでは、読者の共感から入る | 冒頭に総論を置く | 記事の型で選ぶ。場面から入るなら 2〜3 文にとどめ、最初の見出しより前に総論を置く。技術ブログと重要なお知らせは結論から入る |
| 段落の長さ | Web では短く改行する | 1 段落 1 トピックで 4〜8 文 | トピックで区切る。重要な違いや話題の切り替わりは、1〜2 文の段落で際立たせてよい。1〜2 文の段落が続いたら確かめる。4〜8 文は目安としてここに記録するだけにする |
| まとめ | 記事の最後で要点を繰り返す | 結論は総論の繰り返しで新情報を書かない。力を入れるのは総論 | 書籍。まとめは省いてよく、置くなら 1〜2 文 |

## 7. このスキルで定めた判断

次は、資料がそのまま求めている規則ではなく、このスキルの用途から定めた方針です。

| 判断 | 採用する理由 |
| --- | --- |
| 一次情報がなければ、書く前に質問する | ベースラインで、一次情報のない依頼に一般論で応えたため |
| 質問できないときは `【要追記】` つきの草稿と不足リストを返す | 一般論で埋めた記事より、追記箇所が分かる草稿のほうが公開までの作業が少ないため |
| 字数を一般論で埋めない | ベースラインの観察と、Google のガイドに基づく |
| 導入に、題材に即した場面を 2〜3 文まで置ける | 所有者のレビューで、結論と比較条件から始めた記事は、読者が自分の状況と重ねられなかったため（8 節）。長い背景の導入はベースラインで AI 定型として現れたので、長さは 2〜3 文に抑える |
| ノウハウ、比較、提案の記事では、まず場面から入る導入を検討する | 見直しの途中の評価で、比較記事の書き直しが場面を検討せずに結論から入り、変更前と同じ形の導入になったため。場面を書けなければ結論から入るので、全記事の定型にはならない |
| 汎用の煽りと場面を「題材を差し替えても成り立つか」で見分ける | 共感の導入を残しつつ、どの記事にも貼れる定型を防ぐため |
| 想定の場面は、読者を主語にした条件の形で書く | 想定の場面が、実際の出来事や引用と誤認されないようにするため |
| 技術ブログと重要なお知らせは結論から入る | 読者が結果や自分への影響を探して読む記事に、共感の導入を強制しないため |
| 緩急の規則に、避ける形（全段落の短文化、問いかけで始まる節の連続、冗談、俗語、感嘆符）を添える | 「楽しく読める」を、新しい定型や演出に置き換えないため |
| 文体の既定を「22 歳くらいの書き手が、専門知識のない読者に説明する文章」にする | 所有者の決定。公文書のような堅さと、幼い語りの両方を避ける目安にする |
| 一人称は、実際の体験か筆者の判断を示すときだけ使う | 「そこで僕は」のような語りが、幼く、筆者を不必要に前に出したため（8 節） |
| 本文の文体を、依頼者への返答の口調やキャラクターと分ける | 依頼者との会話の一人称や語尾が、公開する記事に入り込むのを防ぐため |
| 比較表のセルを 5 つの表記（対応、非対応、条件付き、記載なし、要確認）に限る | セルに異なる種類の説明が混ざり、同じ条件で比べられなかったため（8 節） |
| 「記載なし」を「非対応」と書かない | 資料に説明がないことを非対応と書くと、確かめていない事実を断定することになるため |
| 書き直しで、下書きから引き継いだ事実と、今回確かめた事実を分ける | 下書きの推測（「×（たぶん）」など）が、確かめた事実として公開されるのを防ぐため |
| 置き換え表の形にする | 出力の形の問題には、禁止より書き換え先を示すほうが効くため |
| 書籍の手順 11 を要約文の読み直しに置き換える | エージェントは時間をあけて読み直せないため |
| キーワード設計を扱わない | ユーザーの決定。読者の目的を決めるところまでを扱う |
| 自社の意見や推奨も作らない | 一次情報のない草稿で、会社が決めていない推奨が結論として書かれたため（最終レビューでの指摘） |
| 書き直しでは下書きの文末（です・ます、常体）を保つ | 指定のない書き直しで、常体の下書きが「です・ます」に変わるのを防ぐため。筆者を前に出す一人称の語りは、文末と違って保たない |
| 根拠のない「と思われる」は確からしさを残す | 社内メモの推量が、公開記事で断定に変わるのを防ぐため |

## 8. 所有者のレビューで見つかった失敗（2026-10-11）

このスキルで比較を含むオウンドメディアの記事を書き直したところ、所有者のレビューで次の 4 つの問題が見つかりました。
関係した規則は、所有者の指摘と当時の SKILL.md を照らして特定したものです。

| 問題 | 関係した規則 | 見直し |
| --- | --- | --- |
| 冒頭から結論や比較条件を並べたため、情報は伝わるが、読者が自分の状況と重ねられなかった | リードは総論にし、背景は 1 文まで。悩みの導入は「結論と一次情報で始める」に書き換える。リードの要点と見出しの順を一致させる | 入り方を記事の型で選ぶ。場面から入る導入を認め、総論は最初の見出しより前に置く。導入はすべての節を予告しなくてよい |
| 全編が同じ調子で、説明や表が続き、読む楽しさや緩急がなかった | 緩急についての規則がなく、1〜2 文の段落を疑う規則と、並列する節を 1 つ目の形を写して書く規則があった | 「緩急をつける」の節を足した。並列でそろえる範囲を見出し、要約文、箇条書きの形に絞り、説明の厚みは重要度で変えてよいとした |
| 「そこで僕は、」のような語りが幼く、筆者を不必要に前に出した | 文体の既定が文末（です・ます）だけで、語りの調子を決めていなかった | 「文体を決める」の節を足した |
| 比較表のセルに異なる種類の説明が混ざり、同じ条件で比べにくかった | 比較記事の型が、候補の並べ方しか決めていなかった | 比較表の作り方を参照ファイルに分け、比較の条件の書き方と 5 つの表記を決めた |

事実を作らないこと、1 段落 1 トピック、簡潔さ、読者が先の展開を予測できることは、見直しの後も変えていません。
