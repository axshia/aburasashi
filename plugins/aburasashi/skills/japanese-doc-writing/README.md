# Japanese Doc Writing

[Skill catalog](../README.md)

日本語のドキュメントを、読み手が「何のページで、自分は何を決めればよいか」を冒頭の 10 秒で分かるように書くスキルです。
調べたことの全量を書き出さず、冒頭に前提・推奨・決めてほしいことを置き、本文を 1 画面に収め、詳細は末尾の「付録」に移します。
読み手は現役のエンジニアとし、専門用語と識別子は言い換えずに使います。

## 使い方

```text
$japanese-doc-writing で、次の調査メモを、チームに相談するための資料にしてください。
決めてほしいのは移行の進め方です。

ここに調査メモを貼り付けます。
```

```text
$japanese-doc-writing で、この設計メモをレビューしてください。まだ書き換えないでください。
```

Claude Code では、プラグイン名を含むスラッシュコマンドでも呼び出せます。

```text
/aburasashi:japanese-doc-writing この調査結果をドキュメントにしてください。
```

## 書き換えの例

変更前：

> # もろもろまとめ
> ### プランの比べ
> （5 プラン × 8 観点の表）

変更後：

> # 注文テーブルの移行の進め方の相談
> 店舗向けの注文テーブルを、EC の注文と共通の構成へ移行します。
> 移行の進め方を、店舗チームと決めたいです。
>
> 推奨は〇〇です。

タイトルと冒頭の 3 行で、何のページで、誰が何を決めるのかが分かるようにしています。
プランの比較表は、付録に移します。

## 適用範囲

- 対象：設計メモ、調査結果、移行計画、比較資料、相談資料、データモデルの解説、手順書、チケット、wiki や Notion のページ、Markdown ファイルの執筆、推敲、レビュー。
- 対象外：セッション中の返答（`japanese-native-writing`）、PR の文面（`japanese-pr-writing`）、コードコメントと spec の説明文（`japanese-code-comment-writing`）、社外に公開する記事（`japanese-article-writing`）。
- 通常の入力：文書化したい情報と、誰が何を決める（知る）ためのページか。分からなければ、書く前に確認します。
- 外部への書き込み：文面の作成だけを依頼した場合、外部のサービスへは書き込みません。
