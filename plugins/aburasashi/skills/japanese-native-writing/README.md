# Japanese Native Writing

[Skill catalog](../README.md)

セッション中の返答と、依頼された日本語ドキュメントを、読み手がその場で次の行動を決められる文章にするスキルです。
結論と結果を先に置き、実施済み・未確認・未実施・不明・不足を分け、複数案は同じ観点で並べて判断を 1 つ求めます。
専門用語は初出時に括弧で補足し、太字とコード書式は必要な箇所だけに使い、図解は関係を示す必要がある場合に限ります。

## 使い方

```text
$japanese-native-writing で、次の作業状況をユーザー向けの報告にしてください。
やっていないことと、判断が必要なことを分けてください。

ここに作業メモを貼り付けます。
```

```text
$japanese-native-writing で、新メンバー向けのローカル環境構築手順を書いてください。
確認していない環境は未確認として書いてください。
```

Claude Code では、プラグイン名を含むスラッシュコマンドでも呼び出せます。

```text
/aburasashi:japanese-native-writing この調査結果を、結論から先にまとめてください。
```

日本語で返答する最初の機会、コンテキスト圧縮の後、日本語ドキュメントを書き始めるときに読み込みます。

## 書き換えの例

変更前：

> 対応状況のご報告です。まず読み込み処理を修正し、テストを追加して実行しました。以上です。

変更後：

> 読み込み処理を修正し、ユニットテストは通りました。戻り値の型を変えたので、呼び出し側の 2 か所に修正が要ります。その 2 か所も私が直してよいか、判断をお願いします。

したこと、読み手に起きること、求めること、の順に置き換えています。
実機での確認をしていなければ、実施済みに含めず未確認として書きます。

## 適用範囲

- 対象：ユーザーへの日本語の返答（説明、進捗報告、調査結果、選択肢の提示）と、依頼された日本語ドキュメント（設計メモ、手順書、調査報告）。
- 対象外：PR のタイトル・本文・レビュー返信（`japanese-pr-writing` が担当）、日本語以外の文章、コードコメントやコミットメッセージの文体。
- 通常の入力：報告したい事実、または文書化したい情報。ネットワークアクセスは不要です。
- 維持する情報：コード、コマンド、パス、識別子、エラー文、URL。
- 補わない情報：情報源にない手順、値、設定、エラー文。これらは不足として示します。

返答を「です・ます」にすることは、ユーザーやリポジトリの指定がない場合の既定値です。
ユーザーが常体で書いていれば、返答も常体に合わせます。
