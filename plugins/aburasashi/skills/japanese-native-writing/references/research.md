## 1. 結論と結果を先に置く

公用文作成の考え方は、結論を早めに、できれば最初の段落で示すことを求めています。
BLUF、逆ピラミッド、Google、Microsoft、GOV.UK も、読者が最後まで読まないことを前提に、冒頭で要点を示す点で一致します。
このスキルでは、冒頭段落に「何をしたか」「読み手に何が起きるか」「読み手に何を求めるか」の 3 点を置く形に具体化しました。
3 点目は、返答を読んだ人がそのまま行動に移れるようにするための、このスキル独自の追加です。

## 2. 複数案と意思決定

ADR は Context / Decision / Consequences の型を定め、Rust RFC は不採用案と理由を必須にし、Google の設計文書文化は代替案のトレードオフを重視します。
Amazon の one-way door / two-way door は、案の比較そのものではなく、戻せるかどうかで判断の重さを変える考え方です。
このスキルでは、案ごとに利点、欠点、可逆性を同じ観点で並べ、戻せない選択を明示する形にしました。
推奨案を先頭に置くことを規定した一次資料は見つからなかったため、スキル独自の採用方針です。

## 3. 実施状態と確からしさ

Anthropic の憲法と OpenAI Model Spec は、不確実なときはそう言い、実行できないことは明示するよう求めています。
SRE のポストモーテムは、うまくいったこと、いかなかったこと、運が良かったことを分けて書きます。
IPCC は確からしさを段階語で表し、文部科学省の和訳が日本語の語彙を与えています。
このスキルでは、事実を実施済み、未確認、未実施、不明、不足の 5 状態に分けます。
この 5 分類は資料が直接定めたものではなく、ベースライン検証で観察した混同（未確認を実施済みに含める、情報源にない事実を補う）を防ぐために定めました。
数値幅は、根拠のない数値を書く誘惑を避けるため添えません。

やさしい日本語ガイドラインは、対象読者の負担を減らすために推測表現を避けて断定するよう求めており、方向が逆です。
このスキルは不確実性の明示を優先し、断定できる箇所は断定する、という両立を採ります。

## 4. 専門用語の補足

公用文作成の考え方は、専門用語を言い換えるか説明を付けることを、やさしい日本語ガイドラインは説明の併記を、Google と Microsoft は略語の初出時にスペルアウトと括弧書きを求めています。
このスキルでは、初出時に括弧で 20 字前後の説明を添え、以後は省く形にしました。
補足しない用語（読み手が先に使った用語と、固定の一般略語）を定めたのは、判断を安定させるためのスキル独自の方針です。

## 5. 強調記号

GOV.UK は強調目的の太字を使わず、GitHub Docs は連続 5 語以内、Google と Microsoft は太字を UI 要素に限ります。
Nielsen Norman Group は、ハイライトが本文の 30% を超えると走査を妨げると述べています。
公用文作成の考え方と JTF スタイルガイドには、太字やコード書式の規定がありません。
このスキルでは、英語圏の規定を日本語の返答に当てはめ、太字を「決定を求める点、戻せない操作、未完了の事項」の 3 種類に限りました。

## 6. 図解

Google Technical Writing は 1 図に 1 段落分の情報、キャプションで要点を先に示すことを求めています。
IETF は ASCII 図をプレーンテキストでの必須表現とし、JIS X 8341-3 は非テキストコンテンツに代替テキストを求めます。
UAX #11 は、全角文字が等幅表示でも幅が異なることを規定しており、AA（ASCII アート）で日本語ラベルの桁が揃わない根拠です。
図解する条件（要素 3 つ以上、かつ関係を文章で書くと読み手が図を組み立て直す必要がある）は、資料が定めたものではなく、このスキルで定めた判断です。
Mermaid と ASCII 図の使い分けを論じた一次資料は見つかりませんでした。

## 7. 会話としての分かりやすさと文書構成

Grice の 4 格率、GOV.UK の一対一で話しかける文体、Google Conversation Design の一度に 1 つの質問、Cowan の約 4 チャンクは、いずれも読み手の処理容量が有限であることを前提にしています。
このスキルの「読み手が次の行動を決められること」という定義は、これらを返答の目的として言い換えたものです。
文書構成は Diátaxis の 4 類型、Google の読者定義、Microsoft の走査しやすい構成、公用文作成の考え方の文書構成を組み合わせました。

## 8. このスキルで定めた判断

次は、資料がそのまま要求している規則ではなく、このスキルの用途から定めた方針です。

| 判断 | 採用する理由 |
| --- | --- |
| 冒頭段落に「求めること」まで含める | 返答を読んだ人がそのまま行動に移れるようにするため。 |
| 事実を 5 状態に分ける | ベースライン検証で、未確認と実施済みの混同、情報源にない事実の補完が観察されたため。 |
| 確からしさは段階語のみ | 根拠のない数値を書く誘惑を避けるため。 |
| 推奨案を先頭に置く | 判断を求める返答で、読み手が最初に見る位置に推奨を置くため。一次資料の規定はない。 |
| 補足しない用語を固定する | 判断を安定させるため。 |
| 太字を 3 種類に限る | 節ラベルや注意書きの飾りに太字が使われる傾向を止めるため。 |
| 図解の条件を要素数と関係で定める | 図が有効な場合だけ描くため。 |
| PR 文面は扱わない | `japanese-pr-writing` と役割を分けるため。 |

## 調査時に得た再利用上の注意

文化庁と Amazon の PDF は、取得ツールの要約では本文を読めなかったため、ダウンロード後にテキスト抽出して該当箇所を確認しました。
資料を更新する際は、発行元の現行ページと本文の版・日付を照合してください。
Cowan（2001）と Sherman Kent（1964）は原典に直接アクセスできず、二次資料経由の確認です。

通常の返答やドキュメント作成のたびに、これらの資料を再取得する必要はありません。
基準の更新や出典確認を依頼された場合に読み直してください。
