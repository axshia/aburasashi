# Codex への依頼手順

Claude Code で PR のタイトルや本文を作る・直すときに、文案を Codex の `gpt-6.1-terra`（Terra 6.1）に書かせる手順です。
Codex（GPT）がこのスキルを読んでいる場合は、この手順を使わずに自分で書きます。

## 依頼の前に集める情報

Codex のセッションには、Claude との会話が引き継がれません。
次の情報を Claude が集め、依頼文に書きます。

- 対象 PR の番号、または差分の範囲（base と head のブランチやコミット）。
- 既存の PR 本文を直す依頼では、元の本文。
- ユーザーの指示。書き方の例、文体、PR テンプレート、「タイトルだけ」などの範囲の指定を含めます。
- 確認済みの検証結果と、その根拠。実施していない検証や失敗した検証も、その状態のまま書きます。
- 情報源で確定できなかった点。

## 依頼文の書き方

依頼文は、スクラッチパッドなどリポジトリ外の一時ファイルに保存します。
依頼文には、上の情報に加えて次を明記します。

- `$japanese-pr-writing` スキルを使うこと。Codex 側にスキルが入っていない場合に備え、このスキルの `SKILL.md` の絶対パスも書き、読むよう指示します。パスはこのファイルのディレクトリから解決します。
- Codex はこのスキルの「Claude Code では文案を Terra 6.1 に書かせる」の節を適用せず、自分で書くこと。
- ファイル、ブランチ、PR を変更せず、文案だけを返すこと。
- 返す内容：タイトル、本文、インラインコメントの案（ファイル、行、説明文）、情報源で確定できず確認が必要な点。

## 呼び出し方

codex プラグイン（`openai-codex`）が入っていれば、それを使います。
Agent ツールで `subagent_type: "codex:codex-rescue"` を呼び、プロンプトの先頭に `--fresh --model gpt-6.1-terra --effort high` を付けます。
続けて「読み取り専用で実行し、ファイルを変更しないでください」と書き、依頼文のパスを読んで従うよう指示します。
`codex:codex-rescue` は、読み取り専用の指示がなければ書き込み可能なモードで Codex を起動します。
`codex:codex-rescue` はスキルではなくサブエージェントなので、`Skill` ツールではなく Agent ツールで呼びます。

プラグインがなく codex CLI が使える場合は、次のように実行します。

```bash
codex exec -m gpt-6.1-terra -c model_reasoning_effort=high -s read-only \
  -C <リポジトリのパス> -o <返答を保存するファイル> - < <依頼文のパス>
```

文案を受け取るまで、PR の作成や編集に進みません。
ユーザーが既存の Codex のスレッドやセッションを指定した場合は、そのスレッドのモデルが `gpt-6.1-terra` であることを確かめ、`--resume` や `codex exec resume` で依頼文を送ります。

## モデルを使えない場合

codex プラグインも codex CLI もない場合、未認証の場合、`gpt-6.1-terra` の指定が受け付けられない場合は、別のモデルで代用しません。
Claude が文案を書くこともしません。
ユーザーに、Terra 6.1 で依頼できない理由と、再開する方法を伝えます。
例として、未設定や未認証なら `/codex:setup` を、モデル名が受け付けられないなら利用できるモデル名の確認を案内します。

## 返った文案を確かめる

Claude は、返った文案をこのスキルの「意味を固定してから書き換える」の観点で、集めた情報と照合します。
事実、検証状態、条件、技術的な文字列の食い違いは、Claude がその語句を直します。
文の構成や言い回しまで変える必要がある場合は、根拠を添えて Codex に直させます。
文章全体を Claude が書き直すことはしません。
照合した文案を、ユーザーの依頼に応じて提示するか、PR に反映します。
Codex が返した確認が必要な点は、本文に入れず、Claude がユーザーに短く伝えます。
