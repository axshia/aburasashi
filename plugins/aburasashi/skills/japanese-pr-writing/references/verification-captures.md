# 動作確認とキャプチャの掲載

画面の挙動が変わる PR で、実際に動かして確かめた結果とキャプチャを本文に載せるための指針です。
テストが通っても、レビュアーは画面を見ないと、見た目と流れを確かめられません。

動作確認そのものを依頼されていない場合は、キャプチャを作らず、未確認として本文に書きます。
複数のユーザーや状態をまたぐ確認を PR に記録する場合は `playwright-pr-qa`、録画が要る場合は `playwright-e2e-recording` を使います。

## 確認する流れを決める

- 確認する流れは、チケットや依頼のゴールから決めます。
- 変更した流れに加え、影響しないはずの既存の画面も確認します（例: 片方の管理画面からログアウトしても、もう片方の管理画面はログインしたままであること）。

## 本文への書き方

- 本文に動作確認の節を置きます。リポジトリのテンプレートにスクリーンショットの欄があれば、そこに書きます。
- 冒頭に、確認した環境を 1 文で書きます（例: ローカル環境、認証はフェイクを使用）。
- 確認したことは 1 つのリストにし、確認済みは `[x]`、未確認は `[ ]` で区別します。各項目は「操作すると、結果になること」の形で書き、項目の下に画像を置きます。
- 同じ画面になる確認（例: ログアウト後に管理画面を開き直す）は、画像を増やさず文で書きます。
- 対象外で確認していないことは、`[ ]` の項目として、対象外であることと未確認であることを書きます。

例:

> ローカル環境（認証はフェイクを使用）で確認しました。
>
> - [x] 0 バイトの `empty.png` を選んで「確認画面へ」を押すと、エラーが表示され、確認画面にリダイレクトされないこと
> - [x] エラーの表示後も、保存済みの画像が残っていること
> - [ ] 1 バイト以上で中身が画像でないファイルは、本 PR の対象外で、未確認です

## 撮影

- 開発用のオーバーレイ（デバッグ用のトースト、プロファイラの表示など、画面に固定表示される要素）が画面に重なる場合は、撮る直前に非表示にします。画面の中身には手を加えません。
- 撮った画像は、開いて確かめます。全体の画像で肝心の文字が読めないときは、その部分を切り出した拡大画像を添えます。
- 写るアカウントやデータは、開発用のダミー（例: `@example.com`）に限ります。

## 添付

- 画像は、Git の管理外の一時ディレクトリに置きます。PR のためだけの画像をコミットしません。
- 添付の手順は、共通の [GitHub への添付の手順](../../../references/github-attachments.md)に従います。
- 添付は GitHub への書き込みです。本文の掲載と同じく、ユーザーの確認のあとに行います。
- 添付したあとに本文を読み直し、画像の参照が GitHub の添付 URL に置き換わり、ローカルのパスが残っていないことを確かめます。PR のページでも、画像が表示されることを確かめます。
