# Logical Thinking — 論理思考

[Skill catalog](../README.md)

仕様・要件策定、UI設計、UX設計、マーケティング思考を少しでも行うときに起動し、目的・比較基準・証拠・制約を分けるスキルです。
新規の検討から使い、違和感の調査、方式の比較、判断理由の説明にも適用します。
現状を説明するだけで終わることや、未実装・未設定を恒久的な要件として扱うことを防ぐための判断手順を提供します。
UI、API、データ分析、運用などに使えます。一般的な方式が常に最善だとは扱いません。

## 使い方

通常はスキル名を指定せず、たとえば「予約のキャンセル仕様を決めたい」「この画面のボタン配置を考えて」「誰に何を訴求するか整理して」と依頼します。
実装や文章作成の一部に小さな設計判断がある場合も、判断を始める前に起動する条件です。
明示的に指定する場合は次のように使います。

```text
$logical-thinking この導線は一般的なサービスと違う気がします。
現状を調べて、目的に対して妥当か評価してください。
```

```text
$logical-thinking この設計を続けるべきか検討してください。
決定済みの要件と、今の実装に由来する制限を分けてください。
```

```text
/aburasashi:logical-thinking なぜこの判断になったのか、記録から分かることと推定を分けて説明してください。
```

## 適用範囲

- 使う場面：仕様・要件策定、UI／UX設計、マーケティング思考を含む作業。新規作成、修正、レビュー、小さな判断も対象です。期待とのずれ、方式の比較、根拠や原因の検討にも使います。
- 広げない場面：事実だけの報告、提案を禁じた調査、単純な翻訳・整形、新しい判断を伴わない決定済み方針の実行。仕様やUIなどの用語が含まれるだけでは再設計しません。
- 推定した目的は仮説として扱います。調査から提案へ進めても、実装や公開の許可は追加されません。
- 必須ツールや外部サービスはありません。根拠の調査で必要になったネットワーク・ツールだけを、依頼の範囲内で使います。
- 言語・文体はユーザーの指定に従います。日本語の表現やPRの文面は、それぞれのライティングスキルと併用できます。

## 構成と評価

- [SKILL.md](SKILL.md)：短い判断手順と回答の完了条件。
- [回答例](references/examples.md)：登録、API、分析、事実限定の調査で、判断の違いを示す架空例。
- [評価入力](references/evaluation-inputs.json)：期待する回答を含まない、独立した10ケース。
- [起動評価入力](references/activation-inputs.json)：新規検討と小さな判断の6ケース、判断を伴わない作業の2ケース。
- [評価手順・採点基準](references/evaluation.md)：評価入力と分離した確認項目。

短い共通原則だけでは判断の適用をモデルに委ねる部分が残り、複数段階の自動処理を導入すると実装と呼び出しの負担が増えます。
このスキルは、会話で選ばれた「短い判断手順＋異なる題材の回答例＋評価ケース」を採用しています。
低い推論設定や旧世代モデルでの品質を保証するものではありません。
構造検証と実際の回答品質は別に評価し、対象モデル・設定で未実行の結果を合格とは扱いません。

評価で見つかった失敗は、特定の正解を常設ルールにせず、どの判断が抜けたかを確認して手順・例・ケースの必要な部分だけを更新します。
