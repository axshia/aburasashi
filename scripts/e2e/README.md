# Playwright のスクリプトをすぐ実行する

録画処理と PR 連携を再利用する場合は、[Playwright E2E Recording](../../plugins/aburasashi/skills/playwright-e2e-recording/SKILL.md) を使う。
このディレクトリには、動作を確かめた単独実行用スクリプトを残している。

`uv` と Google Chrome をインストールした環境で、リポジトリのルートから実行する。
Playwright は各スクリプトの依存指定から `uv` が用意する。
普段使っている Chrome とは別のセッションで検証する。

## note.com の記事を開いて録画する

```sh
uv run scripts/e2e/note-keyword.py
```

実行する操作は次のとおり。

1. `https://note.com/` を開く。
2. 「注目キーワード」の3番目のテーマをクリックする。
3. 「人気の記事一覧」の先頭の記事をクリックする。
4. 記事の上部からページ最下部まで段階的にスクロールする。

「注目キーワード」はテーマ一覧のため、記事を読むにはテーマからもう一度リンクを開く。
テーマ名や記事 URL は固定せず、実行時の表示順から選ぶ。

開始時に表示される一時ディレクトリへ、次のファイルを保存する。

| ファイル | 内容 |
| --- | --- |
| `recording-01.webm` | ブラウザの表示領域を録画した動画（1440 × 1000、音声なし） |
| `01-home-selection.png` | ホームで選んだ3番目のカード |
| `02-article-selection.png` | テーマ一覧で選んだ先頭記事 |
| `03-destination-top.png` | 遷移先の上部 |
| `04-destination-bottom.png` | 遷移先の最下部 |
| `result.json` | 合否、選択したリンク、スクロール位置、動画のパス |
| `trace.zip` | Playwright の操作記録 |

最下部の判定にはスクロール位置とページの高さを使う。
高さが変わらない最下部を連続して観測できなければ成功にしない。
記事下のおすすめが追加で読み込まれるため、最初に取得したページの高さだけで判定しない。
note が遷移後に計測用のクエリを消す場合があるため、同じ記事かどうかは URL のドメインとパスで照合する。
既定では120回のスクロールを上限とし、途中で失敗した場合も可能な範囲で動画と `failure.png` を残す。
録画はブラウザのセッションを閉じてから確定するため、終了時にテスト用ウィンドウが閉じる。

動画エンコーダーが見つからない場合は、一度だけ実行する。

```sh
uv run --with playwright==1.62.0 playwright install ffmpeg
```

別の経路を指定する場合は、`--target keyword-page` で3番目のテーマ一覧まで、`--target featured-article` で「今日の注目記事」の3番目を開く。
一覧が無限スクロールの場合は最下部に到達できず、検証が失敗することがある。

## Google の検索結果を検証する

```sh
uv run scripts/e2e/google-search.py --keep-open --captcha-wait-seconds 300
```

`test` を検索し、広告を除いた先頭の検索結果を開く。
CAPTCHA が出た場合は、テスト用 Chrome で手動認証すると処理が再開する。
このスクリプトはスクリーンショットと操作記録を保存する。

いずれも終了コード `0` は成功、`1` は失敗を表す。
Google では認証待ちなどの停止を `2` で表す。
